# kernel-lift — 从圆环到平面，再把交圆投回去
## Overview
- Hook / question：一条直线分不开两类点；换个看法，能不能分开？
- Audience：中国硕士生，弱数学基础；按动画与停留时间手算约 50 秒，单场景。
- Key Insight：平面与碗面的交圆投回二维成为圆边界；不是压扁整张平面。
- Narrative pattern：Problem → transformation → resolution；先看失败，再改变表示，最后回到原问题。
- FLOW：直线不够 → 倾斜抬点 → 平面分开 → 点积捷径 → 交圆投回。
## Emotional arc
好奇（问题卡）→ 困惑（步骤1）→ 部分明白（步骤2–3）→ 可分的惊喜（步骤4）→ 精确捷径（步骤5）→ aha 与满足（步骤6，交圆下降）。
## Persistent skeleton / layout
- 保留浏览器的 14 蓝点、20 红点及确定性半径/角度生成式；全程复用同一批点。
- 一枚 tilt tracker 同时控制 az=0.5t、el=π/2+(0.32−π/2)t、cy=200+70t；沿用浏览器 oblique projection，k=54，高度系数=0.55。
- 图心 x=225；正俯视恰是二维坐标 (225+54x,200−54y)。右侧 x=430..620 专供带背景的卡片。
- 倾斜时未抬点的 y≤200+70t+121.5cos(1.2508t)<335；加 4px 点半径仍小于 339。
- 抬升时 y≥270−54×2.25×sin(0.32)−54×0.55×2.25²×cos(0.32)>89；点半径后仍大于85。
- 平面半边长2.45，斜视顶点 x≈45..405、y≈157..270；所有数据点、坐标轴及卡片均在安全框内。
## Step 1 · stage 0 · 为什么直线不够？
Purpose：建立红外蓝内的矛盾。 Visual：点出现，一条实线平移试分，再移除；绝不留下虚线 X。
Math attached：只标类别，尚不堆公式。 short：蓝在里面、红在外面，直线总会切错。
Technical：同一条 Line 用 Transform；结束移除，关键画面停留≥1.2s。
## Step 2 · stage 1 · 倾斜是否改了数据？
Purpose：区分换视角与抬高度。 Visual：同一坐标轴和点从正俯视倾斜，三条轴逐渐可见，所有点仍在底面。
Math attached：M 标 x₁、x₂、x₃；T 注明“先换视角，还没抬点”。 short：先倾斜看：所有点仍在原来的底面。
Technical：仅一个 tilt tracker 驱动视角；轴标签移动而不逐帧重建 LaTeX。x₃ 标签放在轴顶**左侧**（轴顶右侧有抬升后的红点 OUTER[3]，r=2.25 碗圈顶部也从轴顶上方经过）；所有轴标签 z=9，高于点（3/5）与平面（4）。
## Step 3 · stage 1 · 新高度从哪里来？
Purpose：距离平方成为高度。 Visual：点沿竖直落线升起，四个等高圆从底面升成碗。
Math attached：φ(u)=(u₁,u₂,u₁²+u₂²)；“保留位置”/“新增：到原点的距离²”；蓝 r<0.9 ⇒ x₃<0.81，红 r≥1.75 ⇒ x₃≥3.0625。旁白说明记号：u 只是某个点的名字，u₁、u₂ 是它在 x₁、x₂ 轴上的坐标；φ 读作 phi，表示“把点变成新坐标”的规则。
short：离原点越远，新增的高度就越大。 Technical：四圈半径0.5、1、1.5、2.25；先运动后公式；所有圈显式加入场景。
## Step 4 · stage 2 · 平面真的能分开吗？
Purpose：看见线性可分。 Visual：黄色半透明平行四边形在高度2显现，蓝下红上。
Math attached：x₃=2；0.81<2<3.0625；平面标签引线接到平面角。 short：黄色平面夹在中间：蓝在下，红在上。
Technical：显式 add 平面，透明度 tracker；蓝点在平面后、红点在平面前；停留≥2s。
## Step 5 · stage 3 · 算法必须真的抬点吗？（≈7.3 s）
Purpose：用两个真实数据点把 kernel 的定义算一遍，看见“同一个数、两条路”。
Visual：淡出 fmap/bounds 卡、平面标签与引线；平面、碗圈、其余 32 个点调暗。高亮蓝点 u=INNER[12] 与红点 v=OUTER[0]：底面位置白圈（标 u、v），抬升后位置黄圈（标 φ(u)、φ(v)），黄色虚线竖线连接（v 抬得很高、u 只抬一点）。右栏两张上下叠放的卡片（右栏是唯一空位，故上下排而非左右排；两条路的前两项放在同一列、结果放在同一列）：
- ① 先抬高成 3-D 点，再点积：φ(u)=(0.60, −0.24, 0.42)，φ(v)=(2.04, 0.15, 4.18)；φ(u)′φ(v)=0.60×2.04+(−0.24)×0.15 / +0.42×4.18 / =1.224−0.036+1.756 / =2.944 ≈ 2.94。卡片出现时 Indicate 抬升黄圈。
- ② 直接用核：只用二维的 u、v：K(u,v)=u₁v₁+u₂v₂+(u₁²+u₂²)(v₁²+v₂²) / =0.60×2.04+(−0.24)×0.15 / +(0.60²+(−0.24)²)(2.04²+0.15²) / =1.224−0.036+1.747 / =2.935 ≈ 2.94，末行旁注“没有造出 3-D 点”。卡片出现时 Indicate 底面白圈。
- 两张卡的中间和（三位小数）与结果行都对齐在 ① 的“=”列；kcard 先对齐再按 body 尺寸画边框，所有行留在卡内（右栏 x≤626）。
- 最后两个 2.94 同时加黄框，卡下写“两条路，同一个数”。
Math attached：章节记号 K(𝐮,𝐯)=φ(𝐮)′φ(𝐯)（粗体 u、v，撇号点积）；第三项（新高度）统一黄色。所有数字在 Python 里由真实坐标算出（f-string）：坐标两位小数，每个乘积按显示数字手算保留三位（1.224、−0.036、1.756 / 1.747），再求和 ①=2.944、②=2.935，代码 assert 两者都舍入为 2.94；numpy 核对不舍入时 φ(u)′φ(v)=K(u,v)=2.943614…（选这对点正是因为两条路按显示数字手算仍一致）。
旁白补充：dual 只用点积的出处（上一章 c28：dual 的目标里数据只以点积 x_i′x_j 出现，预测式里也只有点积 x_i′x）；“多项式核、RBF”后注明“这两种核本章后面马上讲”；说明 2.944 与 2.935 的差别只来自舍入。
short：两条路算出同一个数：核不用造 3-D 点。
Technical：标记为静态 mobject（本步 tilt/lift 不变），下一步开头与交圆淡入同一个 play 里淡出，并恢复点、平面、碗圈的不透明度；旁白 say 由同一组数字拼出，并说明本例 3 维时两条路一样快、高维/无限维时核才省。本例映射不同于章节后面纯二次多项式核的映射。
## Step 6 · stage 4 · 哪个东西投回二维？（aha）
Purpose：准确连接平面与圆边界。 Visual：先在黄色平面上画高度2的交圆；平面淡出，交圆在斜视中单独下降到0；点回到底面，最后视角返回正俯视，原交圆变为决策圆。
Math attached：联立 x₃=x₁²+x₂² 和 x₃=2 得 x₁²+x₂²=2、r=√2；只投影交集，不压扁平面。
short：只把交圆投回去，变成围住蓝点的边界。 Technical：circle_z 从2到0独立动画；保留同一圆；交圆出现、下降、最终圆均停留≥1.2s。
## Colour meanings / Takeaway
- 蓝=内类，红=外类；黄色=当前分隔平面/交圆/结论；灰=轴、落线、碗与解释。背景统一 BG。
- Takeaway：新增高度，让两类能被平面分开 / 交圆投回去，才是原空间的边界 / 核直接算特征点积：精确而非近似。旁白记号与章节一致：φ(𝐮)、K(𝐮,𝐯)=φ(𝐮)′φ(𝐯)。
- 算术：0.25+0.65=0.9，0.9²=0.81；1.75²=3.0625；1.75+0.5=2.25，2.25²=5.0625；0.81<2<3.0625；r²=2⇒r=√2。
